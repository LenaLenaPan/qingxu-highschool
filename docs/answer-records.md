# 逐题作答与数理化输入

状态（2026-09-21）：数据库迁移已应用；页面源码已完成，尚未构建、推送或上线。
遵循仓库 README：用户明确说“构建”“推送上线”或“集中构建”后再发布。

## 学生操作

- 到学习进度页登录原有账号，进入练习后自动读取记录。
- 输入后先缓存本机，再自动保存；以页面上方“作答记录”的状态为准。
- 初次遇到已有本机内容时，确认保存到当前账号；已有云端内容可恢复，或把本机另存为一次尝试。
- 提交后保留首答快照。订正栏继续保存，后续新增图片标记为订正图。
- 同时在两台设备编辑会检测版本冲突，不自动覆盖另一台设备。
- 分数、上下标、根号、向量和化学式有填写模板；符号键盘支持集合、运动、化学常用符号。
- 图片支持 JPG/PNG/WebP，手机可选择相册或拍照。最长边压缩至1800px，私有保存。HEIC需先转换。
- TXT/JSON作为可选备份继续保留。离线HTML只做本机保存，不上传。
- 照片和公式按原作答保存；本功能不自动识别手写内容，也不自动判分数理化解答。

## 实现与权限

`src/progress-sync.ts` 向答题模块共享现有 Supabase 客户端和登录态；须在获准构建时更新原有 bundle。
`public/shared/nav.js` 给各科页面加载 `answer-records.js`，数理化额外加载 `science-input.js`。
第二轮引擎提供适配器，保存题目版本、70题答案、不确定标记、查词次数、用时、评分结果和订正。
已有数理化输入框使用稳定ID；静态试题的题块会补充首思路、首答、订正输入区。
已有第一轮英语题可保存逐题表单；其旧引擎的完整计时/计分恢复不在本次重构范围。

`learning_answer_attempts` 通过 user_id 和 RLS 限制本人读写，匿名会话不可用。
服务端触发器维护版本和提交时间，并保留不可改写的 `first_submission`。
更新必须同时匹配 id 和 version；发生并发冲突时保留本机缓存，由学生选择恢复或另存。
`learning-answer-photos` 为私有桶，文件路径绑定账号和作答ID；没有客户端替换或删除图片的策略。
预览通过5分钟有效的签名链接打开，界面不存永久公开链接。

题目内容实质变更时，应更新第二轮 revision；其他卷在 html 根节点增加/更新 data-answer-version，避免错配旧答案。
账号切换会停止同步并要求刷新，不能自动把上一个账号的页面内容上传给新账号。
旧设备从未上传的答案仍需在原设备打开原页面，确认导入；系统不能凭空找回历史记录。
